# 04 · 权限：为什么普通应用能读写

> 这一页讲机制，不讲"填哪个值"。每台车的白名单内容不同，需要你自己从车上确认。

---

## 1. 两道前置条件

普通应用要读写 VHAL，通常要同时满足：

1. **能装上**：通过安装门槛（签名/白名单等，因车而异）；
2. **能拿到 CarService**：通过 CarService 的入口校验。

装不上是安装问题，拿到 manager 失败是权限问题，两者要分开排查。

---

## 2. CarService 的入口校验

调用链大致是：

```
App
  → Car.createCar / connect
    → ICarImpl.getCarService
      → CarServiceUtils.isHaveSecurityPermission(callingPid)
        → 取 Binder 调用方的进程名
        → 与一份硬编码/配置的名单比较
          → 不在名单：抛 SecurityException
          → 在名单：返回对应 manager
```

关键点：

- 校验的依据是**调用方进程名**，不是包名、UID 或签名；
- 名单的具体内容因车型/版本而异，需要从 `services.jar` / `CarService.apk` 反编译确认；
- 进程名可以在 `AndroidManifest.xml` 的 `<application android:process="...">` 里声明。

> 本仓库不提供具体进程名。你需要从自己车机的 CarService 里找，并自行评估风险。

---

## 3. 为什么"进程名"会成为信任依据

通常是为了让系统应用/预装应用免申请复杂权限：

- 系统应用数量多，逐个配 `signature` 权限麻烦；
- 进程名容易拿（`ActivityManager` 查一下就有）；
- 实现简单，兼容老代码。

代价是：**进程名不是安全边界**。应用可以声明同名进程，校验就失去区分能力。

---

## 4. 属性层的权限检查

拿到 manager 之后，属性读写还有一层检查。常见实现有两种：

| 实现 | 表现 |
|---|---|
| 正常 `assertPermission` | 无权限抛 `SecurityException` |
| 检查结果被丢弃 | 无论有没有权限都放行 |

第二种在部分定制系统上存在：方法调了 `checkCallingOrSelfPermission`，但返回值没用。
表现就是"明明没有权限，却能读写"。

判断方法：

1. 反编译 `ICarImpl` / `CarPropertyService`；
2. 看 `assertPermission` 有没有真的抛异常；
3. 实车用一个没有声明权限的应用试读。

---

## 5. 安装门与 CarService 门的关系

| 门 | 作用 | 失败表现 |
|---|---|---|
| 安装门 | 让 APK 能装进车机 | `INSTALL_FAILED_*` |
| CarService 入口 | 让应用能拿到 manager | `SecurityException: not in white list` |
| 属性权限 | 让具体属性可读写 | `SecurityException` / 静默失败 |

三者独立。装上了不等于能拿到 manager，拿到 manager 不等于每个属性都能写。

---

## 6. 边界与风险

- 通过入口校验后，能拿到的 manager 不止一个；
- 同一个 manager 下可能同时暴露舒适性、车身、动力属性；
- **能拿到不等于应该操作**，尤其不要碰动力/制动/转向/电源；
- 不同 OTA 版本可能修复入口校验或改变名单；
- 修改进程名、包名可能影响应用更新、后台保活与系统识别。

---

## 7. 自己确认权限的方法

只读方式：

```bash
# 看当前应用的进程名
adb shell ps -A | grep <your.package>

# 看 CarService 相关日志
adb logcat -s CarService CarServiceUtils ICarImpl

# dump CarService 状态
adb shell dumpsys car_service
```

反编译方式：

1. 从车机拉取 `CarService.apk` 或 `services.jar`；
2. jadx 反编译；
3. 搜索 `isHaveSecurityPermission`、`getCarService`、`assertPermission`；
4. 看名单字段和比较逻辑。

---

## 8. 安全建议

- 只在自己车上验证；
- 先在只读路径上确认能拿到 manager，再考虑写入；
- 不要为了"能读写"而修改系统分区或替换系统应用；
- 不要把具体名单、包名、进程名提交到公开仓库；
- 如果发现入口校验可以被轻易绕过，按 [SECURITY.md](../SECURITY.md) 的方式披露。
